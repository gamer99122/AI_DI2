# 服務生命週期詳解

## 概述

.NET 的 DI 容器提供三種服務生命週期：
- **Transient**：暫時性
- **Scoped**：範圍性
- **Singleton**：單例性

正確選擇生命週期對應用程式的效能和正確性至關重要。

---

## Transient（暫時性）

### 特性
- 每次從容器請求服務時都會創建**新的實例**
- 使用完畢後由垃圾回收器（GC）回收
- 最簡單但可能最消耗資源

### 註冊方式
```csharp
services.AddTransient<IMyService, MyService>();
services.AddTransient<MyService>(); // 註冊具體類別
```

### 使用場景
- ✅ 無狀態的服務
- ✅ 輕量級的物件
- ✅ 每次都需要全新狀態的服務
- ✅ 不需要共享資料的服務

### 範例
```csharp
public interface IGuidGenerator
{
    Guid Generate();
}

public class GuidGenerator : IGuidGenerator
{
    private readonly Guid _instanceId = Guid.NewGuid();

    public Guid Generate() => _instanceId;
}

// 註冊為 Transient
services.AddTransient<IGuidGenerator, GuidGenerator>();

// 每次請求都是新實例
var gen1 = serviceProvider.GetService<IGuidGenerator>();
var gen2 = serviceProvider.GetService<IGuidGenerator>();

Console.WriteLine(gen1.Generate()); // 不同的 GUID
Console.WriteLine(gen2.Generate()); // 不同的 GUID
```

### 注意事項
- ⚠️ 如果物件創建成本高，避免使用 Transient
- ⚠️ 注意記憶體消耗
- ⚠️ 實作 `IDisposable` 的物件會被容器追蹤直到 Scope 結束

---

## Scoped（範圍性）

### 特性
- 在同一個**範圍**（Scope）內是**同一個實例**
- 不同範圍會創建不同實例
- ASP.NET Core 中，每個 HTTP 請求就是一個範圍

### 註冊方式
```csharp
services.AddScoped<IMyService, MyService>();
```

### 使用場景
- ✅ 資料庫上下文（DbContext）
- ✅ 工作單元模式（Unit of Work）
- ✅ 每個請求需要共享狀態的服務
- ✅ 需要追蹤請求過程中變化的服務

### 範例
```csharp
public class RequestContext
{
    public Guid RequestId { get; } = Guid.NewGuid();
    public DateTime RequestTime { get; } = DateTime.Now;
}

// 註冊為 Scoped
services.AddScoped<RequestContext>();

// 在同一個 HTTP 請求中
using (var scope = serviceProvider.CreateScope())
{
    var ctx1 = scope.ServiceProvider.GetService<RequestContext>();
    var ctx2 = scope.ServiceProvider.GetService<RequestContext>();

    Console.WriteLine(ctx1.RequestId == ctx2.RequestId); // True - 同一個實例
}

// 不同的請求（Scope）
using (var scope1 = serviceProvider.CreateScope())
using (var scope2 = serviceProvider.CreateScope())
{
    var ctx1 = scope1.ServiceProvider.GetService<RequestContext>();
    var ctx2 = scope2.ServiceProvider.GetService<RequestContext>();

    Console.WriteLine(ctx1.RequestId == ctx2.RequestId); // False - 不同實例
}
```

### ASP.NET Core 中的 Scope
```csharp
// 每個 HTTP 請求自動創建一個 Scope
public class MyController : ControllerBase
{
    private readonly RequestContext _context;

    public MyController(RequestContext context)
    {
        _context = context; // 這個請求期間都是同一個實例
    }

    [HttpGet("action1")]
    public IActionResult Action1()
    {
        return Ok(_context.RequestId);
    }

    [HttpGet("action2")]
    public IActionResult Action2()
    {
        return Ok(_context.RequestId); // 同一個請求，相同的 RequestId
    }
}
```

### 注意事項
- ⚠️ 在非 Web 應用中需要手動創建 Scope
- ⚠️ 不要在 Singleton 服務中注入 Scoped 服務
- ⚠️ DbContext 應該使用 Scoped

---

## Singleton（單例性）

### 特性
- 整個應用程式生命週期只有**一個實例**
- 首次請求時創建，之後都使用同一個實例
- 應用程式關閉時才會釋放

### 註冊方式
```csharp
// 方式 1：讓容器創建實例
services.AddSingleton<IMyService, MyService>();

// 方式 2：提供已存在的實例
var instance = new MyService();
services.AddSingleton<IMyService>(instance);

// 方式 3：使用工廠方法
services.AddSingleton<IMyService>(sp => new MyService());
```

### 使用場景
- ✅ 設定物件（Configuration）
- ✅ 快取服務（Cache）
- ✅ 日誌服務（Logger Factory）
- ✅ 全域共享的資料
- ✅ 無狀態的工具類別

### 範例
```csharp
public class ApplicationCache
{
    private readonly ConcurrentDictionary<string, object> _cache = new();

    public void Set(string key, object value)
    {
        _cache[key] = value;
    }

    public object Get(string key)
    {
        _cache.TryGetValue(key, out var value);
        return value;
    }
}

// 註冊為 Singleton
services.AddSingleton<ApplicationCache>();

// 整個應用程式都是同一個實例
var cache1 = serviceProvider.GetService<ApplicationCache>();
var cache2 = serviceProvider.GetService<ApplicationCache>();

cache1.Set("key", "value");
Console.WriteLine(cache2.Get("key")); // "value" - 共享狀態
```

### 注意事項
- ⚠️ **必須是執行緒安全的**
- ⚠️ 避免持有大量記憶體
- ⚠️ 不要注入 Scoped 或 Transient 服務到 Singleton
- ⚠️ 注意記憶體洩漏風險

## 生命週期對照表

| 特性 | Transient | Scoped | Singleton |
|-----|-----------|--------|-----------|
| **實例創建** | 每次請求 | 每個範圍 | 首次請求 |
| **實例數量** | 多個 | 範圍內一個 | 全域一個 |
| **記憶體消耗** | 較高 | 中等 | 較低 |
| **執行緒安全** | 不需要 | 不需要 | **需要** |
| **狀態共享** | 無 | 範圍內共享 | 全域共享 |
| **適用場景** | 無狀態服務 | DbContext、UoW | 快取、設定 |

## 生命週期選擇指南

### 選擇 Transient 當：
```csharp
// ✅ 無狀態、輕量級
services.AddTransient<IEmailValidator, EmailValidator>();
services.AddTransient<IPasswordHasher, PasswordHasher>();
```

### 選擇 Scoped 當：
```csharp
// ✅ 資料庫操作
services.AddScoped<IDbContext, MyDbContext>();
services.AddScoped<IUnitOfWork, UnitOfWork>();

// ✅ 請求追蹤
services.AddScoped<IRequestLogger, RequestLogger>();
```

### 選擇 Singleton 當：
```csharp
// ✅ 設定和快取
services.AddSingleton<IConfiguration>(configuration);
services.AddSingleton<IMemoryCache, MemoryCache>();

// ✅ 工廠
services.AddSingleton<ILoggerFactory, LoggerFactory>();
services.AddSingleton<IHttpClientFactory, HttpClientFactory>();
```

## 危險的混用模式

### ❌ 反模式 1：Singleton 注入 Scoped
```csharp
public class MySingleton
{
    private readonly MyScoped _scoped; // ❌ 危險！

    public MySingleton(MyScoped scoped)
    {
        _scoped = scoped; // Scoped 服務會被 Singleton 持有，無法正確釋放
    }
}
```

**問題**：Scoped 服務的生命週期被延長到 Singleton，導致記憶體洩漏。

**解決方案**：使用 `IServiceScopeFactory`
```csharp
public class MySingleton
{
    private readonly IServiceScopeFactory _scopeFactory;

    public MySingleton(IServiceScopeFactory scopeFactory)
    {
        _scopeFactory = scopeFactory;
    }

    public void DoWork()
    {
        using var scope = _scopeFactory.CreateScope();
        var scoped = scope.ServiceProvider.GetRequiredService<MyScoped>();
        // 使用 scoped
    }
}
```

### ❌ 反模式 2：Singleton 注入 Transient（有狀態）
```csharp
public class MySingleton
{
    private readonly MyTransient _transient; // ⚠️ 可能有問題

    public MySingleton(MyTransient transient)
    {
        _transient = transient; // Transient 變成了 Singleton
    }
}
```

**問題**：原本應該每次都新建的 Transient 服務被固定了。

### ✅ 正確的依賴方向
```
Transient → Transient ✅
Transient → Scoped    ✅
Transient → Singleton ✅

Scoped → Transient    ✅
Scoped → Scoped       ✅
Scoped → Singleton    ✅

Singleton → Transient ⚠️ (無狀態可以)
Singleton → Scoped    ❌ 禁止
Singleton → Singleton ✅
```

## 生命週期驗證

在開發環境中啟用驗證：
```csharp
var host = Host.CreateDefaultBuilder(args)
    .UseDefaultServiceProvider(options =>
    {
        options.ValidateScopes = true;      // 驗證範圍
        options.ValidateOnBuild = true;     // 建置時驗證
    })
    .Build();
```

這會在執行時檢測到生命週期錯誤並拋出例外。

## Console 應用程式中的 Scope

```csharp
var services = new ServiceCollection();
services.AddScoped<MyScopedService>();

var serviceProvider = services.BuildServiceProvider();

// 創建 Scope
using (var scope1 = serviceProvider.CreateScope())
{
    var service = scope1.ServiceProvider.GetRequiredService<MyScopedService>();
    // 使用服務
} // Scope 結束，服務被釋放

// 新的 Scope
using (var scope2 = serviceProvider.CreateScope())
{
    var service = scope2.ServiceProvider.GetRequiredService<MyScopedService>();
    // 這是新的實例
}
```

## 實務建議

### 1. 預設選擇 Scoped
對於大多數業務邏輯服務，使用 Scoped 是安全且高效的選擇。

### 2. 資料庫上下文使用 Scoped
```csharp
services.AddDbContext<MyDbContext>(options =>
    options.UseSqlServer(connectionString),
    ServiceLifetime.Scoped); // 預設就是 Scoped
```

### 3. 快取使用 Singleton
```csharp
services.AddSingleton<IMemoryCache, MemoryCache>();
services.AddSingleton<IDistributedCache, RedisCache>();
```

### 4. HttpClient 使用工廠模式
```csharp
services.AddHttpClient<IMyApiClient, MyApiClient>(); // 內部管理生命週期
```

### 5. 背景服務使用 Singleton
```csharp
services.AddSingleton<IHostedService, MyBackgroundService>();
```

## 除錯技巧

### 查看服務描述
```csharp
foreach (var service in services)
{
    Console.WriteLine($"{service.ServiceType.Name}: {service.Lifetime}");
}
```

### 追蹤物件創建
```csharp
public class MyService : IDisposable
{
    private static int _instanceCount = 0;
    private readonly int _instanceId;

    public MyService()
    {
        _instanceId = Interlocked.Increment(ref _instanceCount);
        Console.WriteLine($"建立實例 #{_instanceId}");
    }

    public void Dispose()
    {
        Console.WriteLine($"釋放實例 #{_instanceId}");
    }
}
```

## 總結

選擇正確的生命週期：

1. **預設使用 Scoped**：安全且高效
2. **無狀態輕量用 Transient**：如驗證器、格式化工具
3. **全域共享用 Singleton**：如快取、設定
4. **避免跨生命週期注入**：特別是 Singleton → Scoped
5. **啟用開發驗證**：及早發現問題

記住：**選錯生命週期可能導致記憶體洩漏、多執行緒問題或效能下降！**
