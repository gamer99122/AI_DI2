# 依賴注入基礎概念

## 什麼是依賴？

當類別 A 需要使用類別 B 的功能時，我們說「A 依賴於 B」。

```csharp
public class EmailService
{
    public void SendEmail(string to, string message)
    {
        Console.WriteLine($"發送郵件到 {to}: {message}");
    }
}

public class UserService
{
    private EmailService _emailService = new EmailService(); // UserService 依賴 EmailService

    public void RegisterUser(string email)
    {
        // 註冊邏輯...
        _emailService.SendEmail(email, "歡迎註冊！");
    }
}
```

## 傳統方式的問題

### 問題 1：緊耦合
`UserService` 直接創建 `EmailService` 實例，兩者緊密耦合。

### 問題 2：難以測試
無法替換 `EmailService` 為測試用的假物件（Mock）。

### 問題 3：違反單一職責
`UserService` 不僅要處理用戶邏輯，還要負責創建 `EmailService`。

### 問題 4：難以替換實作
如果要改用 SMS 發送通知，需要修改 `UserService` 的程式碼。

## 依賴注入的解決方案

```csharp
// 1. 定義介面
public interface INotificationService
{
    void Send(string to, string message);
}

// 2. 實作介面
public class EmailService : INotificationService
{
    public void Send(string to, string message)
    {
        Console.WriteLine($"發送郵件到 {to}: {message}");
    }
}

// 3. 透過建構函數注入
public class UserService
{
    private readonly INotificationService _notificationService;

    // 依賴從外部注入，而非內部創建
    public UserService(INotificationService notificationService)
    {
        _notificationService = notificationService;
    }

    public void RegisterUser(string email)
    {
        // 註冊邏輯...
        _notificationService.Send(email, "歡迎註冊！");
    }
}
```

## DI 的三種注入方式

### 1. 建構函數注入（Constructor Injection）- 最推薦
```csharp
public class MyService
{
    private readonly IDependency _dependency;

    public MyService(IDependency dependency)
    {
        _dependency = dependency;
    }
}
```

**優點**：
- 明確表示必要的依賴
- 物件創建後立即可用
- 支援不可變性（readonly）

### 2. 屬性注入（Property Injection）- 較少使用
```csharp
public class MyService
{
    public IDependency Dependency { get; set; }
}
```

**缺點**：
- 依賴可能為 null
- 不清楚哪些是必要的依賴

### 3. 方法注入（Method Injection）- 特殊情況
```csharp
public class MyService
{
    public void DoSomething(IDependency dependency)
    {
        // 使用 dependency
    }
}
```

## .NET 的 DI 容器

.NET 內建的 DI 容器位於 `Microsoft.Extensions.DependencyInjection` 命名空間。

### 基本使用流程

```csharp
// 1. 創建服務容器
var services = new ServiceCollection();

// 2. 註冊服務
services.AddTransient<INotificationService, EmailService>();
services.AddTransient<UserService>();

// 3. 建立 ServiceProvider
var serviceProvider = services.BuildServiceProvider();

// 4. 解析服務
var userService = serviceProvider.GetRequiredService<UserService>();
userService.RegisterUser("user@example.com");
```

## 三種服務生命週期

### Transient（暫時性）
每次請求都創建新實例。

```csharp
services.AddTransient<IMyService, MyService>();
```

**使用時機**：輕量級、無狀態的服務

### Scoped（範圍性）
在同一個範圍（Scope）內共享實例。

```csharp
services.AddScoped<IMyService, MyService>();
```

**使用時機**：每個請求（HTTP Request）一個實例，如 DbContext

### Singleton（單例性）
整個應用程式生命週期只有一個實例。

```csharp
services.AddSingleton<IMyService, MyService>();
```

**使用時機**：快取、設定、全域狀態

## 生命週期比較表

| 生命週期 | 創建時機 | 使用場景 | 注意事項 |
|---------|---------|---------|---------|
| **Transient** | 每次請求 | 無狀態服務 | 可能消耗較多資源 |
| **Scoped** | 每個範圍 | DbContext、請求相關 | Web 應用最常用 |
| **Singleton** | 首次請求 | 快取、設定 | 必須執行緒安全 |

## 控制反轉（IoC）

依賴注入是實現控制反轉的一種方式。

### 傳統控制流程
```
主程式 → 創建物件 → 呼叫方法
```

### IoC 控制流程
```
主程式 → 向容器請求物件 → 容器創建並注入依賴 → 呼叫方法
```

## 依賴反轉原則（DIP）

SOLID 原則中的 D：
- 高層模組不應該依賴低層模組，兩者都應該依賴抽象
- 抽象不應該依賴細節，細節應該依賴抽象

```csharp
// ❌ 不好：依賴具體實作
public class UserService
{
    private EmailService _emailService = new EmailService();
}

// ✅ 好：依賴抽象介面
public class UserService
{
    private readonly INotificationService _notificationService;

    public UserService(INotificationService notificationService)
    {
        _notificationService = notificationService;
    }
}
```

## 何時使用 DI？

### 適合使用 DI
- ✅ 需要單元測試
- ✅ 有多種實作方式
- ✅ 依賴外部資源（資料庫、API）
- ✅ 大型專案
- ✅ 團隊協作

### 不一定需要 DI
- ❌ 簡單的工具類別
- ❌ 小型腳本
- ❌ 數值計算類別
- ❌ DTO / Model 類別

## 總結

依賴注入的核心概念：
1. **不要自己創建依賴**：讓容器幫你創建
2. **依賴抽象而非具體**：使用介面而非具體類別
3. **建構函數注入優先**：清楚表達依賴關係
4. **選擇正確的生命週期**：根據需求選擇 Transient/Scoped/Singleton
